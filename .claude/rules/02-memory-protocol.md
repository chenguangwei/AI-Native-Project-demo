# 🔄 记忆管理、会话交接与角色同步协议 (Memory & Handoff Protocol)

> 本协议规范跨会话记忆同步的条件与文件落盘格式，防止因长上下文衰减导致的关键事实遗失与项目方向偏离。

## 1. 实时角色与偏好同步 (Persona & Guidelines Sync)
当准备生成重大技术方案决策或复杂代码实现时：
- **主动探测**：如果仓库中存在 `memory/.current_persona` 文件，必须优先读取并严格遵守其中定义的专业角色定位、代码偏好与严苛约束。
- **动态重载**：`memory/.current_persona` 中定义的特有约束具有最高优先级，应作为当前会话的核心准则执行，直到会话结束或文件被更新。

## 2. 记忆落盘触发条件 (Memory Sync Triggers)
在出现以下情况之一时，AI 必须暂停当前的代码改动，将最新的项目上下文同步并落盘到 `memory/` 目录中：
- 顺利完成了一项重大的阶段性任务或里程碑 (Milestone)。
- 遇到了严重阻塞 (Blocker) 且必须请求人类介入。
- 需要切换上下文，接手一个与当前无关的新任务或重构任务。

## 3. 记忆文件管理机制 (Memory Management)
位于 `memory/` 的核心事实与日志文件应当保持扁平、精简且结构化，避免冗余和重复叙述：

### 📋 `active-task.md` (当前任务清单)
- 仅用于管理当前拆解的树状任务列表，使用 `[ ]` (未开始)、`[/]` (进行中) 与 `[x]` (已完成) 进行状态维护，禁止记录流水账废话。

### 🤝 `handoff.md` (会话交接单)
- **滑动窗口式压缩 (Sliding Window)**：当该交接单行数接近 50 行时，必须使用 `replace_file_content` 将过期的历史记录进行清理和提炼，转为全局视角的现状总结（禁止无限无脑 Append）。
- **标准写入制式**：每次更新必须包含：前置落款（如 `**[前端架构 - 2026-05]**`）、当前提交修改的内容、当前的 Blocker/风险点、接下来的 Next Steps。

### 🧠 `project-facts.md` (避坑事实库)
- 记录本项目特有的隐性约束、特定版本的 Bug 或特殊的依赖脾气，提炼为精炼的技术事实，作为项目后续开发的避坑法则。
